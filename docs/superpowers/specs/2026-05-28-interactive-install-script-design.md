# Interactive Install Script Redesign

**Date:** 2026-05-28
**Status:** Approved

## Goal

Transform `install.sh` from a simple clone-and-install script into an **interactive project scaffolding tool**. Users run `curl ... | bash` and get their own project — with their own name, own secrets, and a clean git history — in the current working directory.

## Flow

```
curl -fsSL https://raw.githubusercontent.com/.../install.sh | bash

1. Check prerequisites (git, node, pnpm, docker)
2. Prompt: "Project name (kebab-case): "
3. Prompt: "Your name (for git config): "
4. Prompt: "Your email (for git config): "
5. Validate all inputs
6. Clone into ./<project-name> (current directory)
7. Search-replace across all text files
8. Auto-generate secrets, write .env
9. Remove .git, git init fresh with user name/email
10. pnpm install
11. Print next steps
```

## Interactive Prompts

Three prompts in order:

```
==> Enter project name (kebab-case, e.g. my-saas-app):
==> Enter your name (for git config, e.g. John Doe):
==> Enter your email (for git config, e.g. john@example.com):
```

**Project name validation:**

- Must match `^[a-z][a-z0-9-]*$`
- Must not already exist as a directory in `$(pwd)`
- On invalid input: print error, re-prompt

**Git name/email validation:**

- Must be non-empty
- On empty input: print error, re-prompt

## Derived Values

For project name `my-saas-app`:

| What | Value |
|------|-------|
| Directory | `./my-saas-app` |
| Root `package.json` name | `@my-saas-app/source` |
| API `package.json` name | `@my-saas-app/api` |
| Web `package.json` name | `@my-saas-app/web` |
| `APP_NAME` (.env) | `my-saas-app` |
| `POSTGRES_DB` (.env) | `my_saas_app_dev` |
| `DATABASE_URL` (.env) | `postgresql://postgres:password@localhost:5432/my_saas_app_dev` |

## Search-Replace

Replace these patterns across all non-binary files (exclude `node_modules/`, `.git/`, `pnpm-lock.yaml`, binary files, images):

| Find | Replace |
|------|---------|
| `@fullstack-monorepo-app/` | `@<name>/` |
| `@fullstack-monorepo/` | `@<name>/` |
| `fullstack_monorepo_dev` | `<name_with_underscores>_dev` |

Files affected: `package.json`, `.env`, `docker-compose*.yml`, `Makefile`, `nx.json`, `tsconfig*.json`, `*.ts`, `*.tsx`, etc.

`pnpm-lock.yaml` is **not** touched — it gets regenerated by `pnpm install`.

## Secret Generation

Auto-generate using `openssl rand -base64 48`:

- `JWT_ACCESS_SECRET`
- `JWT_REFRESH_SECRET`
- `AUTH_SECRET`

All other `.env` values keep defaults from `.env.example` (with project name substituted where applicable).

## Git Reset

```bash
rm -rf "$INSTALL_DIR/.git"
git init "$INSTALL_DIR"
git -C "$INSTALL_DIR" config user.name "$GIT_USER_NAME"
git -C "$INSTALL_DIR" config user.email "$GIT_USER_EMAIL"
git -C "$INSTALL_DIR" add -A
git -C "$INSTALL_DIR" commit -m "Initial commit from template"
```

Git user name and email are set as **local config** (scoped to this repo only), so it doesn't pollute the user's global git config. Clean initial commit, ready for the user to push to their own remote.

## Key Behavioral Changes from Current Script

| Before | After |
|--------|-------|
| Installs to `$HOME/nestjs-nextjs-monorepo` | Installs to `./<project-name>` (current dir) |
| No interactive prompts | Prompts for project name, git user name, git email |
| Secrets are placeholders in `.env` | Secrets are auto-generated |
| Keeps template git history | Fresh `git init` with clean initial commit |
| `package.json` names unchanged | Renamed to `@<name>/source`, `@<name>/api`, `@<name>/web` |
